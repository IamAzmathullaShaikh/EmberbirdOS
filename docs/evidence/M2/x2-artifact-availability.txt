WHY THIS CHECK EXISTS
  M2 section 4.2 allows two routes to the X2 artifact: build it from the locked
  manifest, or acquire a prebuilt "derived from the same manifest" and record its
  URL + SHA-256 + build provenance. Because a from-source build needs ~300+ GB and
  this host has ~104 GB, the prebuilt route was the intended path. This file records
  what that route actually offers - checked against the upstream sources rather than
  assumed - and it is the reason the plan converges back on the build.

CONCLUSION (X2 stays OPEN - this check did not close it)
  There is currently NO prebuilt that can honestly be recorded as X2 evidence:
    * the official channel is paused, so no signed image with build provenance exists;
    * the only mirror carries an Android-11-era image that is demonstrably not built
      from the pinned manifest.
  Recording the mirror image as X2 would mean asserting a provenance that cannot be
  substantiated - precisely the overclaim M2 X7 forbids. So nothing was downloaded and
  no hash is claimed.

WHAT REMAINS AVAILABLE FOR X2
  a) Build from the locked manifest - `mode=build-from-manifest` in
     .github/workflows/guest-build.yml - on a runner with the disk for it (self-hosted
     or a GitHub larger runner). This is the provenance anchor M2 prefers anyway, and
     it re-confirms the committed X1 lock with `repo manifest -r` before building.
     It is the only route that yields a verifiable "built from THIS lock" claim.
  b) An operator-supplied artifact the owner has reason to trust (their own build, or a
     specific image they accept). It can be recorded via `mode=prebuilt-provenance`,
     which captures URL + SHA-256 + size + retrieval time; the image's divergence from
     the pinned manifest must be recorded alongside it, because the lock - not the
     download - is the provenance anchor.
  c) Unrelated to X2's artifact, but it unblocks X3 independently: provisioning QEMU +
     OVMF on this host allows the frozen launcher's -DryRun to resolve and capture the
     exact boot argv. That needs no guest image and is available immediately.
